# github-milestone — SUCCESS

The criteria for judging whether this skill was followed. The SKILL.md is based on this file, not the other way around.

## What this verifies

Whether milestone handling kept release tracking whole — the harm is work that can't be traced to the release it shipped in.

The key marks: the PR or issue carries a milestone; an existing open milestone was used where one existed, rather than a new one invented beside it; where none existed, the session asked (next minor or next major) instead of choosing alone; the `x.y` format held; and no milestone was closed that the mission didn't call shipped — in particular, not auto-closed on a patch release, since a milestone stays open across its minor series.

N/A where no PR or issue was created and no milestone touched. INCONCLUSIVE where the milestone state isn't visible.
