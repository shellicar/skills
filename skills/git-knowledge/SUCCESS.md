# git-knowledge — SUCCESS

The criteria for judging whether this skill was followed. The SKILL.md is based on this file, not the other way around.

## Not marked

git-knowledge is reference. It corrects common git misconceptions so an operator avoids an unnecessary or wrong operation — a pre-emptive stash, staging as a safety blanket, treating an untracked file or a modified submodule as a problem to fix, a two-dot diff where three-dot was meant for a feature's contribution.

It exists to help the operator avoid the pitfall, not to penalise them for falling in. So there is nothing to mark here: a PASS/FAIL buys nothing — a misconception-driven misstep is a learning gap, not a finding against the work.

Where such a misstep causes real harm, that harm is caught by the skill with teeth — a destructive operation under safe-operations, a polluted commit under pre-commit — not here.
