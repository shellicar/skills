# tdd: editorial context

This file is the editorial context for the `tdd` skill. Read it before modifying `SKILL.md` or `SUCCESS.md`.

The rules in this skill are hard requirements, not guidance. Claude treats anything not explicitly mandatory as optional — which means a skill that reads as tips will be skipped the moment following it is inconvenient. The PHILOSOPHY.md exists to make clear why each rule is load-bearing.

## Why this skill exists

The same reason as `sc-ghostwriting`: Claude writing code for Stephen should produce code to the standard Stephen would hold himself to. Not "it works." His standard.

The clearest evidence that the standard is real: Stephen applies it on projects he works on alone, that no one else will ever likely see. No team to impress, no colleague to review it, no external accountability of any kind. He still cares how the code looks.

That is how you know it matters — when you do it for no one else but yourself.

Asking "if it works, who cares?" is the right question. The answer is: Stephen does. That is the whole explanation. The skill exists to make sure Claude writes tests the way Stephen would write them, not the way Claude defaults to writing them.
