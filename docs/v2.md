# Skills v2 — philosophy and plan

2026-07-14. Worked out between the SC and Claude. This is the design the v2
content is built against. V2 lives on its own branch/worktree and nowhere
else: launching from this checkout gets v2 loading; main is v1, untouched.
There are no flags — if something is worth doing here, it is simply how this
branch works.

## Why v2 exists

The v1 belief was that injecting skills up front was cheap because of caching.
The audit data says otherwise: cache reads and writes are 87% of a $7,156
quarter, and the standing prefix (14–48k tokens per session) is paid again on
every turn of every session. Injection cost scales as prefix × turns ×
sessions. Upfront is the most expensive placement for content mostly unused on
any given turn.

## Philosophy

**1. Admission, not retention.** V2 starts from nothing. A line gets in by
earning its place — the failure it prevents can be named — not by surviving a
cut. Nothing is carried because it exists.

**2. The why is load-bearing; justification is not.** A skill states the rule
and the why. The why is what decides the cases the rule never enumerated —
that is its job, and it stays. Justification (persuading the reader the rule
is right) goes. The test: does this why decide unlisted cases, or only defend
the rule?

**3. The channel carries authority.** The same words bind when injected at
launch and merely inform when fetched as a file mid-session. So: anything
that must *bind* rides the injected channel (the core); anything that can
*inform* is fetched from the index. This — more than size — decides core
membership.

**4. The session is incomplete by design, and knows it.** V1 tried to make
every session complete at birth. A v2 session carries a small core and an
index of what else it is entitled to; reading the skill before doing covered
work is part of the work. The reaching habit is itself foundational.

**5. Enforced structure over recited structure.** Where a hook, permission,
or deny-rule can hold a rule, prose stops carrying it. Prose costs tokens
every session and relies on compliance; config costs nothing and does not.
(safe-operations' block lists are the first candidates.)

**6. Authority is an escalation, not ambient.** Default is peers: discuss,
disagree, hold positions with reasons. Decisions are the SC's; accountability
for outcomes is his, always — structure, not tone. A reserved command phrase
escalates one prompt to a directive: the words are the order, no
interpretation, clarifying questions only, no relitigating; scope is that
prompt alone. There is no test — complying with an invoked directive is never
caving. The escalation mechanism is separate from the SC's title/identity;
the address forms no longer carry authority. (Phrase, and the irreversible-
edge rule under directive, still to be settled.)

**7. The proven v1 commitments carry forward as principles** (re-expressed,
not copied): replace the trained success function rather than constraining
it; keep internal state observable where a canary earns its cost; defend
against variance accumulating across the chain (source preservation, digest
never relay); decide by cost asymmetry (ask over guess, irreversible over
reversible, reader's attention over writer's convenience); one word, one
meaning.

**8. Cost is a design input.** The core has a budget (~4k tokens). Every
description is written as a retrieval trigger — WHEN to load, not just what
it is — because in the index model the description is the retrieval
mechanism. --doctor is the scale everything is weighed on.

## Plan

- **Phase 0 — machinery** *(done, this branch)*: FOUNDATIONAL_CORE and
  buildSkillsIndex. (The guard/doctor improvements are main's, done by the SC;
  the branch inherits them.) Still open in this phase: the launchers here use
  buildSkillsIndex unconditionally — no flag.
- **Phase 1 — this document**: philosophy agreed with the SC.
- **Phase 2 — core, from nothing**: write the always-inline tier against the
  budget. Candidates by job, not by v1 name: authority-as-escalation (a few
  lines), the asymmetries, voice, the reaching habit. No `skills:`
  dependencies in core. Settle the escalation phrase and the irreversible-edge
  rule.
- **Phase 3 — enforcement**: move blockable operations from prose to
  claude-sdk-cli permissions/hooks; what remains in prose is only the
  semantic rule no hook can check.
- **Phase 4 — index tier**: skills admitted one at a time as work needs them,
  rewritten to earn admission; descriptions rewritten as retrieval triggers;
  reference material split into companion files.
- **Phase 5 — composition**: per-phase role loading for the handler (kill the
  31-skill union); fix or retire the broken executor/scribe launchers.
- **Phase 6 — measure and merge**: A/B real sessions v1 vs v2; watch the
  usage scripts; when v2 holds, it becomes main.
